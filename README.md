사례관리 실무자의 기록 부담을 낮추고 누적 데이터를 AI로 분석하여, **한정된 복지 자원이 가장 필요한 사람에게 제때 닿을 수 있도록** 돕는 사례관리 솔루션

## **1. 팀 기본 정보**

### **1.1 기관 정보**

시립중랑노인종합복지관은 ‘덕불고필유린의 정신으로 모두가 은혜로운 하나의 세상을 만든다’는 미션 아래 지역사회 어르신들이 존엄한 노후를 보내실 수 있도록 힘쓰고 있습니다. 우리 기관은 평생교육과 취약계층 지원을 넘어, 의료·복지·마을이 연계된 민관협력 중심의 '돌봄통합지원'을 적극 추진하며 어르신들이 살던 곳에서 건강한 노후를 보낼 수 있도록 돕고 있습니다. 사별 어르신의 정서적 자립 프로그램인 ‘도란도란’, 아동성폭력예방을 위한 노인 봉사단 ‘빨간망토 인형극단’ 등 주체적인 사회 참여를 이끄는 특화 사업을 통해 세대가 상생하는 복지 공동체를 선도하고 있습니다.

## **2. AI 솔루션**

### **2.1 문제 정의**

시립중랑노인종합복지관 사례관리 담당자는 단 2명입니다. 이 두 사람이 사례관리 20명, 밑반찬 40명, 무료급식 286명, **총 339명의 취약계층 어르신을 전담**합니다. 담당자들이 바라는 것은 단 하나입니다. 한정된 복지 자원이, 진짜 필요한 어르신에게, 제때 닿는 것. 하지만 지금 시스템은 그것을 가능하게 하지 않습니다.

**\[현장의 현실 : 기록할수록 지치고, 지칠수록 누군가가 빠집니다]**

하루에도 수십 명의 어르신과 나누는 대화를 빠짐없이 기록하는 것은 물리적으로 불가능합니다. 기존 진우시스템은 모바일을 지원하지 않고, 복지관 평가를 위해 정형화된 문장으로 작성해야 하는 기록 부담은 담당자를 지치게 만듭니다. 기록은 줄어들고, 줄어든 기록은 누락을 낳고, 누락은 판단의 공백을 만듭니다. **결국 '누가 더 시급한가'는 데이터가 아닌 담당자의 기억과 감으로 결정됩니다.**

이 공백이 만들어낸 결과는 실제로 확인됐습니다. 지난여름 폭염 대비 선풍기 후원을 배분할 당시, 파편화된 기록 탓에 담당자의 기억에 의존해 대상자를 선정했습니다. **그리고 사후에, 더 열악하고 더 시급했던 어르신이 명단에서 빠져 있었음을 확인했습니다.** 가장 필요한 사람이 가장 먼저 빠지는 역설. 이것이 지금 현장의 현실입니다.

이 문제는 저희 기관만의 이야기가 아닙니다. 타 기관 사례관리 실무 경험자 30명을 대상으로 자체 설문을 진행한 결과, **66.7%가 모바일 미지원으로 인한 현장 기록의 어려움**을 호소했습니다. 과거 기록의 검색·조회 제약과 데이터 요약 부재가 각 40%, 기록 작성 부담이 36.7%로 뒤를 이었습니다. *"축적된 기록에서 핵심 욕구를 한눈에 파악하기 어렵다", "수정할 때마다 삭제 후 재작성해야 한다"* — 현장의 목소리는 하나같이 같은 곳을 가리키고 있었습니다.

지금 시스템의 문제는 단순한 불편함이 아닙니다. **기록이 부담스러워 줄어들고 → 줄어든 기록은 누락되고 → 누락된 기록은 활용되지 못하고 → 결국 자원 배분은 주관에 의존하게 되는** 구조적 악순환입니다. 이 구조 안에서는 아무리 헌신적인 담당자라도 한계에 부딪힐 수밖에 없습니다.

**\[솔루션 : 담당자의 판단을 기억에서 데이터로 바꿉니다]**

결국 이 모든 문제는 하나로 귀결됩니다. **담당자가 '누가 더 시급한가'를 데이터로 판단할 수 없다는 것.** 이것이 저희가 해결하고자 하는 핵심 문제입니다.

이번 솔루션은 두 단계로 문제에 접근합니다. 먼저 **AI 기반 상담기록 다듬기와 모바일 현장기록**으로 기록의 부담을 낮춥니다. 담당자가 현장에서 간단히 메모한 내용을 '다듬기' 버튼 하나로 **복지관 평가 기준에 맞는 정제된 상담기록으로 변환**할 수 있으며, **담당자가 AI의 초안을 직접 검토하고 수정한 뒤 최종 등록하는 구조**로 판단의 주체는 언제나 담당자에게 있습니다. 기록에 쏟던 시간과 에너지가 줄어든 만큼, 지금까지 누락되어 온 어르신의 욕구와 상태가 빠짐없이 데이터로 쌓이기 시작합니다.

축적된 데이터는 그 자체로 자산이 됩니다. **AI가 누적된 상담기록을 분석해 어르신별 욕구 변화와 긴급도를 도출**하고, 담당자는 이를 기반으로 누가 먼저 지원받아야 하는지 데이터로 판단할 수 있습니다. 더 이상 선풍기 한 대를 누구에게 드려야 할지, 기억을 더듬지 않아도 됩니다. **한정된 복지 자원이 가장 필요한 어르신에게, 가장 먼저 닿을 수 있도록.**

***

### **2.2 AI 솔루션 소개**

#### **솔루션 개요**

2명의 담당자가 339명의 어르신을 책임지는 현장에서, **기억이 아닌 데이터로 움직이는 사례관리**를 만들고자 했습니다. 웹 기반 통합 사례관리 플랫폼에 AI를 연동한 **'현장 밀착형 AI 사례관리 에이전트'** 가 그 답입니다. 핵심 기능은 네 가지입니다. **① AI 상담일지 다듬기 ② 모바일 현장기록 ③ 스마트 검색 ④ 욕구·목표 자동분석.**

**\[기록의 부담을 낮추고, 데이터를 쌓습니다]**

담당자가 현장에서 간단히 메모한 내용을 '다듬기' 버튼 하나로 **복지관 평가 기준에 맞는 정제된 상담기록으로 변환**할 수 있습니다. 모바일에서도 현장 기록이 가능해, 지금까지 사무실로 돌아와야만 했던 기록의 공백을 없앴습니다. 이때 AI가 작성한 내용은 바로 저장되지 않습니다. **담당자가 AI의 초안을 직접 검토하고 수정한 뒤 최종 등록하는 구조**로, 기록의 정확성과 전문적 판단은 언제나 담당자에게 있습니다. 기록에 쏟던 시간과 에너지가 줄어든 만큼, 지금까지 누락되어 온 어르신의 욕구와 상태가 빠짐없이 데이터로 쌓이기 시작합니다.

**\[쌓인 데이터를 AI가 분석해, 판단의 근거를 만듭니다]**

축적된 상담기록은 그 자체로 자산이 됩니다. **스마트 검색 기능으로 수개월치 과거 기록을 키워드 하나로 즉시 조회**할 수 있어, 지금까지 기억에 의존하거나 기록을 일일이 뒤져야 했던 시간을 없앴습니다. 여기서 그치지 않습니다. AI는 누적된 상담 데이터를 분석해 **어르신별 욕구 변화와 긴급도를 자동으로 도출**합니다. 선풍기처럼 한정된 후원 자원이 들어왔을 때, 담당자는 더 이상 기억을 더듬지 않아도 됩니다. **가장 시급한 어르신이 데이터로 보이고, 자원은 가장 필요한 곳으로 향합니다.**

담당자의 기억과 주관에 의존하던 방식에서 벗어나, **AI가 누적 데이터를 분석해 의사결정을 보조하는 현장 밀착형 사례관리.** 더 이상 가장 필요한 어르신이 가장 먼저 빠지는 일은 없어야 합니다.

> **⑤** **`.env.local`** **파일(또는 Vercel 환경변수)에 아래 항목 설정** (전체 목록은 `ai-case-management-v2/.env.example` 참고)

각 항목은 데이터베이스 주소와 접근 권한 키로, **외부에 노출되면 안 되는 민감한 정보**가 포함되어 있습니다. 코드에 직접 입력하는 대신 `.env.local`(로컬) 또는 Vercel 환경변수(배포)에만 보관하며, `.env.local`은 GitHub에 업로드되지 않습니다.

```
VITE_SUPABASE_URL=                # Supabase 프로젝트 주소
VITE_SUPABASE_PUBLISHABLE_KEY=    # Supabase 공개(publishable) 키
SUPABASE_URL=                     # 서버에서 쓰는 같은 주소
SUPABASE_PUBLISHABLE_KEY=         # 서버에서 쓰는 같은 공개 키
SUPABASE_SERVICE_ROLE_KEY=        # 서버 전용 서비스 키 (절대 공개 금지)
SUPER_ADMIN_EMAILS=               # /admin 접근 슈퍼 관리자 이메일(쉼표 구분, 서버 전용)
NAVER_MAP_CLIENT_ID=, NAVER_MAP_CLIENT_SECRET=   # (선택) 네이버 지도
```

Google Gemini API 키 등은 `.env.local`이 아닌 **Supabase Edge Function 시크릿에 별도 등록**합니다. (Supabase 대시보드 → Edge Functions → Secrets) `GEMINI_API_KEY`는 필수이고, 복순이를 함께 쓰는 경우 `COMPANION_*` 값도 등록합니다. 이 중 **`COMPANION_MONITOR_SECRET`(모니터 함수 비밀값)은 저장소에 없으며 설치하는 기관이 길고 무작위인 새 값을 직접 정해야** 합니다. 복순이 쪽 마이그레이션 SQL의 자리표시자와 같은 값을 넣고, 값을 넣은 SQL 파일은 커밋하지 않습니다. (`bright-day-talk-v2/README.md` 참고)

> **⑥** Supabase Edge Function 배포: `npx supabase functions deploy <함수명> --project-ref <프로젝트 ID>`\
> **⑦** **`bun install`** **→** **`bun dev`** **명령으로 로컬 서버 실행**\
> **⑧ Vercel 등 클라우드 플랫폼에 배포하여 기관 내 서비스로 운영**\
> **⑨ 운영 보안 설정**: 담당자 가입이 끝나면 Supabase의 **신규 가입(Allow new users to sign up)을 끄고**(담당자를 추가할 때만 잠시 켬), Google Cloud에서 **Gemini API 예산·할당량 한도**를 설정합니다.

**※ Supabase 무료 플랜 사용 시** 저장공간(500MB) 한계를 보완하기 위해 Google Drive와 연동하여 상담 기록 및 첨부파일을 외부에 저장할 수 있습니다. 장기 운영을 계획하는 기관의 경우 이 옵션을 활용하면 비용 부담 없이 안정적으로 운영할 수 있습니다.

단 하나의 복지관만을 위한 솔루션이 아닙니다. **전국 어느 기관이든 현장 상황에 맞게 직접 구축하고 운영할 수 있도록**, 전체 소스코드와 설정 가이드를 함께 공개합니다.

#### **주요 기능**

**해결 아이디어 1. 기록의 부담을 낮춥니다**

*관련 기능 : AI 상담일지 자동 생성, 모바일 현장기록*

담당자가 현장에서 간단히 메모한 내용을 '다듬기' 버튼 하나로 **복지관 평가 기준에 맞는 정제된 상담일지로 변환**합니다. 모바일에서도 현장 기록이 가능해 사무실로 돌아와야만 했던 기록의 공백을 없앴습니다. AI가 작성한 초안은 **담당자가 직접 검토·수정 후 최종 등록**하는 구조로, 판단의 주체는 언제나 담당자에게 있습니다.

**해결 아이디어 2. 쌓인 데이터로 자원을 공정하게 배분합니다**

*관련 기능 : 키워드 검색, 자원 배분 AI 도우미*

수개월치 상담 기록을 **키워드로 즉시 조회**할 수 있습니다. 기억에 의존하거나 기록을 일일이 뒤져야 했던 시간을 없애고, 필요한 정보를 빠르게 찾아 현장 의사결정을 즉시 지원합니다.
여기서 그치지 않습니다. *"오늘 삼계탕 30개가 들어왔는데 누구한테 나가면 좋을까?"* — 담당자가 자연어로 질문하면 **AI가 최근 3개월 상담·제공이력을 기반으로 우선순위 대상자를 추천**합니다. 더 이상 한정된 자원을 누구에게 드려야 할지 기억을 더듬지 않아도 됩니다. **가장 시급한 어르신이 데이터로 보입니다.**

**해결 아이디어 3. AI가 사례관리 계획을 분석하고, 달성률을 추적합니다**

*관련 기능 : 사례관리 계획 자동 추출, 계획 대비 달성률 추적, 연간 변화 분석*

신규 대상자의 적격심사지 또는 기존 대상자의 재사정기록지를 업로드하면, **AI가 문서를 분석해 대상자별 사례관리 계획을 자동으로 추출**합니다. 담당자는 상담기록과 제공이력 등록 시 해당 내용이 어떤 계획 목표에 해당하는지 직접 연동할 수 있으며, 등록된 내용을 바탕으로 **각 어르신의 계획 대비 달성률을 한눈에 확인**할 수 있습니다.
매년 재사정 시 새로운 기록지를 업로드하면, **AI가 작년 대비 욕구 변화와 계획의 달성 여부를 자동으로 분석**해 담당자가 어르신의 변화 흐름을 빠르게 파악할 수 있습니다. 상담기록과 제공이력이 누적될수록, **계획 대비 달성률도 실시간으로 업데이트되어 지원 공백을 사전에 방지**합니다.

**해결 아이디어 4. 개인정보를 철저히 보호합니다**
*관련 기능 : 기관별 접근 제어, Google 로그인, 관리자 승인, 정기 데이터 백업*
사례관리 데이터는 취약계층 어르신의 민감한 개인정보를 담고 있습니다. **기관별 전용 URL**로 타 기관의 데이터에는 접근 자체가 불가능하고, **Google OAuth 인증**을 결합해 허가된 계정만 로그인할 수 있으며, 신규 담당자가 가입하더라도 **관리자가 직접 승인한 이후에만 대상자 정보에 접근**할 수 있습니다.
데이터 보호는 접근 제어에서 그치지 않습니다. Google Drive 연동 설정 시 **주 1회 정기적으로 데이터가 자동 백업**되어, 예기치 못한 상황에서도 소중한 상담 기록이 유실되지 않도록 보호합니다.

**AI 성능 개선 시도**

좋은 아이디어도 실제 현장에서 작동하지 않으면 의미가 없습니다. 개발 과정에서 마주친 문제들을 하나씩 해결하며 현장에서 바로 쓸 수 있는 수준으로 다듬었습니다.

**① 상담일지 품질 문제 — 현장 양식을 AI에게 가르쳤습니다**\
처음에는 메모를 그대로 AI에게 전달했더니 너무 일반적인 문장만 생성됐습니다. 복지관에서 실제로 사용하는 상담일지의 항목 구조(날짜·대상자·상담 내용·욕구·향후 계획)를 AI에게 미리 정의해 줬습니다. **그 결과 현장에서 바로 사용할 수 있는 수준의 상담일지가 생성**되기 시작했습니다.

**② 동명이인 혼동 문제 — 어르신마다 고유 번호를 부여했습니다**\
AI가 이름만으로 어르신을 구별하다 보니, 같은 이름의 어르신 기록을 혼동하는 오류가 발생했습니다. 이름과 함께 각 어르신의 고유 식별 번호를 AI에게 함께 전달하는 방식으로 바꿨고, **이후 혼동 오류가 완전히 사라졌습니다.**

**③ AI 오류 시 기록 유실 문제 — 원본은 반드시 보존합니다**\
AI 응답이 실패하거나 지연될 경우, 담당자가 입력한 원본 메모가 사라질 수 있는 위험이 있었습니다. AI 오류가 발생하더라도 **담당자가 입력한 원본 메모는 반드시 저장되도록** 안전장치를 마련했습니다. 기록 자체가 유실되는 상황을 원천 차단했습니다.

### **2.3 이용자용 가이드**

**이용 전 준비사항**

별도 프로그램 설치는 필요하지 않습니다. 크롬 등 웹 브라우저와 Google 계정만 있으면 됩니다. 단, 처음 사용 전에 반드시 관리자(슈퍼바이저 또는 IT 담당자)에게 본인의 Google 계정 등록을 요청해야 합니다. 등록되지 않은 계정은 로그인 후 접근이 차단됩니다.

스마트폰에서는 브라우저 메뉴의 **'홈 화면에 추가'** 를 선택하면 앱처럼 바로 실행할 수 있습니다. iOS와 Android 모두 지원되며, 현장에서 더욱 편리하게 사용할 수 있습니다.

**실제 이용 방법**

1. 웹 브라우저에서 기관 전용 URL에 접속합니다. (`https://서비스주소/기관별_부여주소` 형태)
2. Google 계정으로 회원가입 후 관리자 승인을 기다립니다.
3. 승인 완료 후 Google 계정으로 로그인합니다.
4. 대시보드에서 담당 대상자를 추가하거나 목록을 확인합니다. (신규 기관의 경우 대상자 등록 후 사용)
5. 상담 기록을 남길 때는 어르신 이름을 클릭 → 상담 탭 → 날짜와 시간을 선택한 후, 현장 메모를 짧게 입력합니다. (예: '파스 필요, 허리 다침, 식사 거름')
6. **AI 자동 생성** 버튼을 누르면 표준 상담일지 형식으로 문장이 자동 완성됩니다.
7. 내용을 확인한 후 저장합니다. 내용이 어색하면 **AI 다듬기** 버튼으로 재생성하거나 직접 수정할 수 있습니다.
8. 신규 대상자의 적격심사지 또는 기존 대상자의 재사정기록지를 업로드하면, **AI가 사례관리 계획을 자동으로 추출**합니다. 상담기록과 제공이력 등록 시 해당 목표에 연동하면 **계획 대비 달성률을 한눈에 확인**할 수 있습니다.
9. 매년 재사정 시 새로운 기록지를 업로드하면 **AI가 작년 대비 욕구 변화와 달성 여부를 자동으로 분석**해 어르신의 변화 흐름을 빠르게 파악할 수 있습니다.
10. 축적된 상담 기록은 **키워드로 즉시 검색**할 수 있습니다. 필요한 정보를 빠르게 찾아 현장 의사결정을 즉시 지원합니다.
11. 한정된 후원 자원이 들어왔을 때는 **자원 배분 AI 도우미**에 자연어로 질문하세요. (예: *"오늘 삼계탕 30개가 들어왔는데 누구한테 나가면 좋을까?"*) AI가 최근 3개월 상담·제공이력을 기반으로 **우선순위 대상자를 추천**합니다.
12. 달력 화면에서는 공휴일·절기와 함께 상담 일정을 월별로 확인할 수 있습니다.

**이용 시 주의사항**

* AI가 생성한 문장은 반드시 검토 후 저장하세요. AI가 사실과 다른 내용을 추가하는 경우 담당자가 직접 수정해야 합니다.
* 상담 날짜와 시간은 실제 상담이 이루어진 시각으로 정확히 입력해 주세요. 추후 욕구 분석 데이터의 기준이 됩니다.
* 어르신의 민감한 개인정보(의료 정보, 가족 갈등 등)는 꼭 필요한 범위 내에서만 기록합니다.

#### 관리자(슈퍼바이저)용

**담당자 등록 및 역할 관리**

신규 기관의 경우, **첫 번째 가입자가 자동으로 관리자**가 됩니다. 이후 관리자가 로그인하여 대시보드에서 추가 담당자를 등록하고 역할을 부여할 수 있습니다.

역할은 세 가지로 구분됩니다.

* **관리자** : 담당자 등록·역할 변경·기관 설정 등 전체 권한
* **직원** : 대상자 상담기록 조회 및 등록 등 실무 권한
* **뷰어** : 데이터 조회만 가능, 수정 불가

등록 방법은 아래와 같습니다.

1. 관리자 계정으로 로그인 후 대시보드 접속
2. 멤버 관리 메뉴에서 추가할 담당자의 Google 이메일 입력
3. 역할(관리자·직원·뷰어) 선택 후 저장
4. 저장 후 해당 계정으로 로그인하면 즉시 사용 가능

**Google Drive 백업 설정 방법**

1. IT 담당자가 Supabase Edge Function에 Drive 연동 시크릿을 등록합니다 (최초 1회 서버 설정)
2. Google 계정을 연동하면 **상담기록, 제공이력, AI 리포트 등 주요 데이터가 자동으로 Google Drive에 백업**됩니다
3. 백업된 파일은 연동된 Google Drive 폴더에서 확인할 수 있습니다

**운영 중 신경 써야 할 사항**

* **담당자 계정 관리** : 퇴사하거나 담당이 변경된 경우, 해당 계정을 **즉시 비활성화**해야 합니다. 비활성화하지 않으면 퇴사자가 어르신의 개인정보에 접근할 수 있습니다.
* **Gemini API 사용량** : Google Cloud Console에서 월별 API 호출량을 주기적으로 확인합니다. 한도 초과 시 AI 기능이 일시 중단될 수 있으므로 사용 요금제를 확인해 두세요.
* **Supabase 플랜** : 무료 플랜은 일정 기간 비활성 시 프로젝트가 일시 정지되어 **서비스 전체가 중단**될 수 있습니다. 장기 운영 시 반드시 유료 플랜으로 전환하거나 Google Drive 백업을 설정하세요.

**운영 전 준비사항**

**운영 중 신경 써야 할 사항**

* **모델 버전 확인** : Gemini 모델은 정기적으로 변경될 수 있습니다. 오류 발생 시 코드 내 모델명을 최신 버전으로 교체하세요.

### **3.1 현장 적용 결과**

이번 솔루션은 시립중랑노인종합복지관 사례관리 담당자 2명이 실제 업무에 활용하는 것을 목표로 개발되었으며, 현재 파일럿 운영 중입니다.

**업무 방식의 변화**

기존에는 담당자가 현장 방문 후 돌아와 기억을 되살려 상담일지를 작성하거나, 시간이 부족할 경우 기록을 생략하는 일이 빈번했습니다. 솔루션 도입 이후 현장에서 단문 메모만 입력해도 AI가 표준 양식의 상담일지를 자동 생성하여, 기록에 소요되는 시간이 크게 단축되었습니다. 특히 **PWA(Progressive Web App) 기술을 적용하여 별도 앱 설치 없이 스마트폰 홈 화면에 아이콘을 추가하는 것만으로 앱처럼 실행**할 수 있습니다. iOS와 Android 모두 지원되며, 담당자가 어르신 댁을 방문한 자리에서 바로 상담 내용을 기록할 수 있어 **현장 기록 누락을 원천적으로 줄이는 환경**이 만들어졌습니다. 담당자는 *"상담기록, 수정, 출력과 같은 전반적인 프로세스가 간소화됐어요"* 라고 피드백했습니다.

**수치로 확인된 변화**

도입 전 기존 시스템에서 상담기록 1건 작성 시 **10분 이상 소요가 56.5%**, 20분 이상 소요도 39.1%로 기록 부담이 높았습니다. 또한 하루 상담기록 작성·관리 시간이 **10분 이상 단축될 것이라는 기대가 56.7%**, 5분 이상 단축 기대도 76.7%로 나타났습니다.

실제 파일럿 운영 결과는 기대를 뛰어넘었습니다. 사례관리 담당자 2명을 대상으로 **1개월간 월간 상담기록지 작성 실적**을 측정하여, 1건당 평균 작성시간·제공이력 누락건수·상담기록 작성건수를 기존 방식과 비교했습니다. *(담당자 자체 측정)*

* 상담일지 1건 작성 시간 : 평균 약 **10분 → 1분** *(약 90% 단축)*
* 월간 제공이력 누락 : **15건 → 2건** *(86.7% 감소)*
* 월간 상담기록 작성 건수 : **22건 → 30건** *(36.4% 증가)*
* 담당자 만족도 설문 : **5점 / 5점**

### **3.2 시행착오와 개선**

**① AI가 목표달성률을 잘못 산출하는 할루시네이션 문제 — 담당자 판단 구조로 전환**

초기에는 AI가 상담기록과 제공이력을 자동으로 분석해 사례관리 계획의 대상자별 목표달성률을 산출하도록 설계했습니다. 하지만 실제로 적용해보니 AI가 상담 내용과 계획 목표 간의 연관성을 잘못 판단하는 경우가 많아 **부정확한 정보가 반복적으로 생성**됐습니다. 복지 현장에서 잘못된 달성률은 단순한 오류가 아니라 잘못된 자원 배분으로 이어질 수 있어 반드시 해결해야 했습니다.

여러 방식을 검토한 끝에, **AI에 전적으로 의존하는 방식 대신 담당자가 판단하는 구조**로 전환했습니다. 상담기록과 제공이력을 작성할 때 해당 내용이 사례관리 계획의 어떤 목표에 해당하는지 담당자가 직접 연동 여부를 판단해 등록하고, 등록된 내용을 바탕으로 **목표달성률을 한눈에 확인할 수 있도록** 했습니다. AI가 모든 것을 자동화하는 것보다, 담당자의 전문적 판단이 더 정확한 데이터를 만든다는 것을 현장에서 직접 확인한 중요한 교훈이었습니다.

**② 데이터가 쌓일수록 느려지는 구조 문제 — 전용 테이블로 분리 중**

초기에는 상담 기록과 서비스 계획 연동 데이터를 `clients.note` 컬럼에 JSON 문자열로 저장하는 방식을 사용했습니다. 하지만 데이터가 쌓일수록 시스템에 부담이 커져 속도가 느려질 수 있다는 한계가 확인됐고, 전용 테이블(`care_plan_action_links`)로 분리하는 작업이 필요했습니다.

이를 위해 새 데이터를 기존 방식과 신규 테이블에 **동시에 기록하는 이중쓰기(Dual-Write) 전략**을 단계적으로 설계했습니다. Phase 3에서 신규 테이블 쓰기를 추가하고, Phase 4에서 읽기를 신규 테이블 우선으로 전환하며, 콘솔 오류가 없는 것을 확인한 후 Phase 6에서 구버전 읽기를 완전히 제거하는 순서입니다. 이 과정에서 `setLinkedIds` 함수의 배열 재할당 버그, 연동 해제 시 상태가 초기화되지 않는 문제 등을 추가로 발견하고 수정했습니다. **서비스 안정성을 최우선으로 하되, 데이터 무결성을 유지하며 전환하는 구조를 직접 설계한 경험**이었습니다. 현재 단계별 전환 중으로, 추후 완전히 분리 관리할 예정입니다.

**③ 남아있는 한계**

AI가 생성하는 상담일지가 복지관 고유의 전문 용어와 문체를 완벽히 반영하지 못하는 경우가 있어 담당자의 수정이 여전히 필요합니다. 절기 및 설날 날짜 데이터는 현재 2028년까지만 하드코딩되어 있어 매년 업데이트가 필요하며, 긴급도 기반 자원 배분 기능은 현재 구현되어 있으나 **정확도 모니터링을 통한 지속적인 업그레이드가 필요**합니다.

기능적 한계 외에도, **솔루션을 3주간 실제 현장에서 가동한 결과, 매주 새로운 피드백과 수정 사항이 발생**했습니다. 현장의 업무 방식과 용어는 기관마다, 담당자마다 다르기 때문에 일회성 개발로 완성되는 솔루션이 아닙니다. **지속적인 현장 모니터링과 버전업이 반드시 필요**하며, 이를 위한 운영 체계를 함께 갖추는 것이 앞으로의 과제입니다.

### **3.3 향후 계획 및 임팩트 확산**

**단기 계획 (2026년 내)**

현재 서비스 제공 계획과 실제 제공 기록을 연동하는 기능을 안정화하여, 계획 대비 이행률을 실시간으로 추적하는 체계를 완성합니다. AI가 누적 상담 기록을 분석하여 어르신별 긴급도와 욕구 충족도를 시각화하는 대시보드를 고도화하고, 한정된 후원 자원이 들어왔을 때 가장 시급한 대상자를 자동으로 추천하는 자원 배분 기능을 **고도화**합니다.

**중기 계획 (2027년)**

현재 시립중랑노인종합복지관 단독 운영에서 중랑구 내 유관기관으로 확산을 추진합니다. 기관별 전용 URL과 접근 권한 구조가 이미 갖추어져 있어, **신규 기관 추가 시 별도 개발 없이 즉시 적용이 가능합니다.** 사례관리 담당자 간 대상자 인수인계 기능과 기관 간 연계 서비스 현황 공유 기능도 추가할 계획입니다.

이러한 확산 가능성은 자체 설문 결과에서도 확인되었습니다. 설문에 참여한 30명은 시립중랑노인종합복지관뿐 아니라 대청종합사회복지관, 시흥시노인종합복지관, 경기도시각장애인복지관 등 여러 지역의 실무자로 구성되었으며, 이들 역시 상담 데이터 누락, 기록 관리의 어려움 등 유사한 현장 문제를 경험하고 있었습니다. 이는 본 솔루션이 특정 기관에만 필요한 시스템이 아니라, 유사한 사례관리 업무 구조를 가진 지역사회 복지기관에 확산·적용할 수 있는 가능성이 있음을 보여줍니다.

**장기 비전**

고령화 사회에서 사례관리 담당자 1인이 감당해야 하는 대상자 수는 계속 증가하고 있습니다. 본 솔루션이 지향하는 것은 AI가 담당자를 대체하는 것이 아니라, AI가 행정 부담을 줄여 담당자가 사람을 더 잘 만날 수 있게 하는 것입니다.

나아가 누적된 어르신별 상담 데이터를 기반으로, **어르신 개인 맞춤형 AI 챗봇(복순이)과 연동하는 쌍방향 모니터링 체계**를 구축하고자 합니다. 담당자가 어르신을 모니터링하는 것을 넘어, 어르신이 직접 챗봇을 통해 자신의 상태와 필요를 전달할 수 있는 구조입니다. 기록의 부재로 사각지대에 놓이는 어르신이 없도록, **전국 지역사회 복지관으로 확산 가능한 표준 모델**을 만들어 나가겠습니다.

### **4.5 개인정보·AI 윤리 항목**

아래 개인정보·AI 윤리 5개 항목에 대한 답변을 작성해 주세요.

1. 어떤 개인정보를 모으고, 어디에 쓰고, 어디로 보내는지 설명해 주세요. (예: 이름·연락처·이용 기록 등 수집 항목, AI 모델·외부 API로 전송하는 경우 포함)

   사례관리 업무 수행을 위해 대상자의 **이름·연락처·생년월일·주소·가족관계·상담 내용·욕구 정보·서비스 제공 기록**을 수집합니다. 수집된 정보는 담당자의 **사례관리 업무 지원과 AI 기반 욕구 분석·자원 매칭**에 활용됩니다. 데이터는 **Supabase(클라우드 데이터베이스)에 암호화하여 저장**되며, AI 다듬기(상담일지 요약) 기능은 담당자가 입력한 메모 텍스트만 전송합니다. AI 슈퍼바이전 리포트 기능은 분석의 정확도를 위해 대상자 이름·상담 내용 등이 포함된 데이터를 전송합니다. **Gemini API는 결제(유료) 등급 키일 때만 입력이 모델 학습에 쓰이지 않는 것으로 안내되며, 무료 등급이면 입력이 제품 개선·학습에 쓰일 수 있습니다. 운영 기관이 키 등급을 확인해야 합니다(아래 '도입 기관이 확인할 것').** 또한 리포트 분석 결과는 기관 담당자만 접근 가능한 폐쇄 환경에서만 활용되며, 외부에 공개되거나 제3자에게 제공되지 않습니다.

2. 개인정보를 수집·활용했다면, 이용자의 동의를 받았는지 또는 동의 없이 써도 되는 근거가 무엇인지 설명해 주세요. (예: 회원가입 시 동의 받음/ 별도 동의 없이 공개된 정보만 사용함 등)

   대상자의 개인정보는 기관(시립중랑노인종합복지관)의 복지 서비스 제공 목적 내에서, **기존 사례관리 등록 절차에 따라 대상자 본인의 동의를 받아 수집된 정보를 활용**합니다. 본 솔루션은 기존에 동의된 정보를 기록·관리하는 업무 도구로, **새로운 개인정보를 별도로 추가 수집하지 않습니다.** AI 분석 기능 도입에 따라 **기관 차원의 개인정보처리방침 갱신 및 이용자 고지를 진행할 예정**입니다.

3. 개인정보를 어떻게 처리하는지, 그리고 AI를 사용한다는 사실을 이용자에게 어떻게 알리는지 설명해 주세요. (예: 서비스 화면에 "AI가 생성한 답변입니다" 표시, 개인정보처리방침 페이지 등)

   수집된 개인정보는 **Supabase PostgreSQL에 암호화하여 저장**되며, **기관별 접근 권한(Google OAuth + 기관 슬러그 URL)으로 허가된 담당자만 열람**할 수 있습니다. AI가 생성한 상담일지는 **자동 생성된 내용임을 담당자가 인지할 수 있도록 구분 표시**되며, **저장 전 반드시 담당자의 확인을 거치도록 설계**되어 있습니다. 서비스 내 **개인정보처리방침 페이지를 별도로 제공**하고 있습니다.

4. AI가 틀리거나 부적절한 답을 했을 때, 사람이 확인하고 고칠 수 있는 절차가 있는지 설명해 주세요. (예: 관리자 검수 화면, 신고 기능, 응답 로그 모니터링 등)

   AI가 생성한 상담일지는 **자동 저장되지 않습니다.** 담당자가 내용을 직접 검토한 후 저장 버튼을 눌러야만 저장되며, 저장 이후에도 **수정 버튼을 통해 언제든지 내용을 변경**할 수 있습니다. AI 다듬기 기능 역시 결과를 즉시 반영하지 않고 **담당자의 최종 확인을 거칩니다.** 모든 AI 출력물은 **담당자의 검토·수정·승인을 거치는 구조로, AI가 단독으로 최종 기록을 확정하는 경우는 없습니다.**

5. AI 사용으로 이용자가 실제로 피해를 볼 수 있는 상황을 어떻게 막고 있는지 설명해 주세요. (예: 잘못된 의료·법률 정보 제공 방지, 생성형AI서비스 학습데이터로 사용되지 않도록 설정 등)

   AI는 **상담 기록 작성, 욕구 분석, 계획 추출 등 보조 역할**을 하며, 서비스 제공 여부나 자원 배분의 **최종 결정은 반드시 담당자가 내립니다.** AI가 생성한 긴급도 우선순위와 욕구 분석 결과는 **의사결정 참고 자료로만 제공**되고, AI의 판단이 곧 결정으로 이어지는 구조를 배제했습니다. 또한 **Gemini API 호출이 실패하거나 응답이 비어 있는 경우 원본 메모를 덮어쓰지 않고 오류를 안내하여 담당자가 직접 저장하도록 설계**되어 있습니다. **Gemini API 키가 결제(유료) 등급일 때만 전송된 데이터가 모델 학습에 사용되지 않는 것으로 안내되며, 키 등급은 운영 기관이 확인해야 합니다.**
